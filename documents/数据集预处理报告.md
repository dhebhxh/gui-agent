# 数据集预处理报告

## 一、 概述

所有原始数据集经过清洗后，均被转换为统一的 `UnifiedSample` 格式。

### 统一输出格式：`UnifiedSample`
```python
class UnifiedSample(TypedDict):
    goal_id: str              # 任务唯一标识符
    goal_desc: str            # 任务的自然语言指令/目标
    image_bytes: Optional[bytes] # 当前时刻的屏幕截图（二进制）
    step: int                 # 当前动作属于该任务的第几步
    action: dict              # 标准化后的目标动作（供模型学习）
    source: str               # 数据来源标识
    metadata: Optional[dict]  # 附加信息（如原始操作、URL等）
```

---

## 二、 Multimodal-Mind2Web

### 2.1 原始核心字段：
  * `confirmed_task` (string): 任务描述。
  * `screenshot` (dict): 包含 `bytes`（截图）和 `path`。
  * `cleaned_html` (string): 清洗后的网页 DOM 树。
  * `pos_candidates` (string/list): 包含目标元素的属性字典（重点含 `bounding_box_rect` 坐标）。
  * `operation` (string): 原始动作描述（如 `{"op": "CLICK", "value": ""}`）。

### 2.2 转换逻辑：

1. 动作映射：将 `operation` 中的 `CLICK` 映射为 `left_click`，`TYPE` 映射为 `type_text`。提取目标框中心点坐标作为 `x`、`y`。若为输入动作，则提取 `value` 作为 `text`。

### 2.3 处理结果

    共扫描样本数: 864
    成功处理数  : 809
    失败总计    : 55
        缺失截图  : 0
        图片损坏  : 0
        目标定位失败: 55
        处理异常  : 0

目标定位失败的具体原因包括：

- 不可见元素污染：HTML 中包含了宽高为 0 的隐藏元素，其 bounding_box_rect 无效。

- 异步加载导致坐标缺失：原始抓取过程中，部分异步渲染元素的 pos_candidates 为空，导致无法匹配目标。

- 越界与错位：部分元素的物理坐标超出了当前网页视口的最大分辨率，属于无效的物理位置。

## 三、 ScreenAgent

### 3.1 原始核心字段：
*   `task_prompt_en` (string): 任务的自然语言指令。
*   `saved_image_name` (string): 当前步骤的截图文件名。
*   `actions` (list): 动作列表。ScreenAgent 的原始动作结构较为复杂，包含多种类型：
    *   `MouseAction`：包含 `mouse_action_type`（如 click）和 `mouse_position`（内含 `width` 和 `height`）。
    *   `KeyboardAction`：包含 `keyboard_action_type`（如 text、press），以及 `keyboard_text`（输入文本）或 `keyboard_key`（按键名称）。
    *   `PlanAction` / `EvaluateSubTaskAction`：包含纯文本的计划描述或子任务评估结果。

### 3.2 转换逻辑：

1. 截图处理：通过本地目录解析 `saved_image_name`，直接读取对应的 `.jpg` 截图的二进制流作为 `image_bytes`。
2. 动作映射：
    *   将 `MouseAction` 的 `mouse_position` 中的 `width` 和 `height` 映射为 `x`、`y`，动作类型转为 `left_click`。
    *   将 `KeyboardAction` 的 `text` 类型映射为 `type_text`（并填入 `text` 字段），`press` 类型映射为 `key_press`（并填入兼容字符串和列表格式的 `key` 字段）。
    *   强制过滤：直接丢弃 `PlanAction` 和 `EvaluateSubTaskAction`等文本节点，保证只保留可执行动作。

### 3.3 处理结果

    遍历 Session 数 : 203
    解析 JSON 文件数: 3005
    成功提取有效样本: 990
    失败/跳过总计   : 4158
    - 缺失/损坏图片 : 0
    - JSON 解析失败 : 0
    - 无效动作(跳过): 4158
    - 处理异常      : 0


无效动作（跳过）的具体原因包括：

- 原始数据中夹杂了大量 `PlanAction`和 `EvaluateSubTaskAction`节点。这些节点只有文本描述，不具备真实的鼠标坐标或键盘按键，属于非执行动作。代码将其判定为无效并强制丢弃，防止模型学习到错误的“纯文本动作”。


## 四、 Verified-WebArena

### 4.1 原始核心字段：
*   `task_id` (int): 任务的唯一标识符。
*   `intent` (string): 任务的自然语言描述。
*   `start_urls` (list): 任务起始页面的 URL 列表。
*   `eval` (string): 用于判定任务是否成功的 Python 评估脚本或配置。
*   `intent_template` (string): 生成该任务意图的模板。

### 4.2 转换逻辑：

1. 环境信息保留：将目标 URL (`start_urls[0]`) 和评估规则 (`eval`) 完整保留在 `metadata` 中，以便后续通过 Playwright 唤起真实网页环境或在强化学习中计算 Reward。
